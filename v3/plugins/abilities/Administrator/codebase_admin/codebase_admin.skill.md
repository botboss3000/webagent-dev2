# Codebase Admin — v3

Use this ability for source work inside the current session workspace. The workspace is separate from the WebAgent host checkout and other application data. Inspect the workspace first. For WebAgent v3 source work, use `workspace_seed` to create a clean source snapshot and Git baseline in `webagent-v3/`. It never imports live data or credentials. For other repositories, report a missing source prerequisite rather than editing a similarly named file elsewhere.

Use `prompt_slot_read` to list or get the current session agent's ordered instruction slots. Each slot has a revision. `prompt_slot_write` can put or delete a slot only after approval; supply the revision you just read (0 to create). A stale revision is rejected. Changes affect newly accepted runs; an in-flight run retains its pinned instructions. Agent owners and delegated administrators manage their own agent; membership and the installation account tier independently restrict use. Installation oversight does not change agent ownership. `__skills__` is reserved and cannot be managed as an ordinary prompt slot. Never store credentials in a prompt slot.

Use `state_inspect` for bounded, read-only facts about the current session. Start with `catalog` to discover available resources. `session` gives title and chat cursor/count; `chat` pages public message previews using an ascending sequence cursor; `runs` gives recent status metadata. The runtime binds the session; there is no session ID, SQL, database path, or encryption key argument. Do not use shell or Python to access application databases.

Read project instructions in the workspace before changing source. Search for the owning file or symbol, then read a focused region. Make the smallest coherent change, use `source_review` to inspect tracked and new files, and verify it with the available workspace commands. For a multi-file edit, `source_patch` applies a checked text diff against the exact review digest and requires approval. The image includes Rust 1.90; use `cargo check` or `cargo test --locked` from `webagent-v3/` for Rust changes, with a bounded command timeout. After verification, call `promotion_propose` with the exact digest from a complete `source_review` and a concise summary. This creates a durable review request; only an installation administrator can approve promotion to live v3 source or reject the proposal. Record what changed and what remains unverified.

The session capability mode also applies: `read_only` withholds mutating tools and denies a queued mutation even if its approval was granted before the mode change. A mode change invalidates pending approvals. `write` still obeys the global policy; it does not turn approval-gated tools into automatic actions.

The Rust policy gate decides whether each tool is allowed or requires approval. A loaded ability does not override that gate. File writes, exact edits, patches, shell commands, and Python execution require approval by default. A command's effect matters more than its name.

This port covers typed current-session inspection, revision-checked prompt slots, source seeding, workspace listing, reading, searching, writing, exact editing, checked patching, change review, shell, and Python. v2 checkout/checkin, automatic repository promotion, and server restart are not available in this ability yet.

Commands run in a fail-closed Linux sandbox: current workspace files and assigned preview ports are available; other workspaces, application state, credentials and control sockets are withheld. The trusted supervisor handles cancellation and descendants. Use Code Index for explicit source freshness and coverage, Git Control for typed fenced version control, Terminal Control for genuine interactive PTYs, and V3 Workspace for durable receipts and fixed locked Cargo tasks. V3 Build uses a separate installation-admin host broker for frozen builds and separately approved development deployment.

`destructive_caution=cautious` strengthens approval for changing operations. Balanced or trusted never raise execution above installation policy, account tier or membership level. Neither Computer Control nor Program Screenshot is included in this coding deployment. Never infer that a catalog declaration has a tested executable adapter.
