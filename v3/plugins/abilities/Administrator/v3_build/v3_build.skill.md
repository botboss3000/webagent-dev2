# V3 development builds

Use `v3_build_work` for coordinated source changes. Call `begin` with a stable task ID before editing, and call `finish` with the current `v3_build_status.inputs_sha256` only after source review and the appropriate workspace checks pass. All registered tasks must be closed. The final close submits one durable job that builds both pinned Rust images, runs their locked tests, checks the frozen source digest, replaces only the V3 development API and loop containers, and verifies their health. A newly opened task, changed source input, expired authorization, or failed test stops replacement. The job retains stopped rollback containers and private rollback artifacts. Poll `v3_worker_job` using the returned job ID; do not infer success from submission.

`v3_build_work.status` reports the open task count and this session's task receipts. A task ID is single use. Repeat the exact `finish` call after an uncertain response to recover its job ID. If the broker restarted during a build, inspect its durable job; interrupted work is never replayed automatically. Reconcile an uncertain deployment before further replacement.

Workspace Cargo checks run through the isolated worker. The host broker owns the Docker boundary; the app and worker have no Docker socket. Installation administrator authority, effective tool policy, and required approval still apply. Finishing a task requires live automatic permission for `v3_worker_submit` throughout the job; revoking it stops deployment. Build inputs include the full allowlisted context and relevant untracked files, but exclude runtime databases and workspaces. Coordinate source writers and the shared target before taking a digest. The registry is shared with Codex through the server-side `buildctl.py` CLI in this ability directory. Codex uses SSH and its own Unix peer identity; it cannot submit arbitrary Docker or shell commands through the broker. The registry covers clients that register work; it cannot detect an unregistered external editor, so source digest checks remain mandatory.

Manual `v3_worker_submit` build and deploy remains a recovery path. Deployment requires this session's successful, unchanged build and a separate authorized call. `v3_build_worker_restart` controls only the older V2 build worker and is not part of the V3 self-update workflow. `login_as_current_user_v3` authenticates the development browser as the current caller for a requested journey; browser login alone is not feature validation.
