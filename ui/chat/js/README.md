# `ui/chat/js/` — chat and session management modules

Split from the original monolithic `chat.js` (1637 lines) and `sessions.js` (2468 lines) into focused modules, each under ~520 lines. Everything flows one direction — no circular imports.

## Chat modules (bubble rendering, streaming, sending, UI)

| Module | Exports | Purpose |
|--------|---------|---------|
| `chat-bubble.js` | `addChatBubble`, `updateLastBubble`, `_fillAgentBubble`, `linkifyText`, `escapeHtml`, `_renderMarkdownBody`, `_formatRelativeTime`, `_refreshAllBubbleTimes`, `_parseCreatedAt` | Bubble DOM creation, markdown rendering (marked + DOMPurify), linkification, relative timestamps. Sets `app.addChatBubble`, `app._linkifyText`, `app._renderMarkdownBody` at module scope. |
| `chat-bubble-actions.js` | `_addBubbleActions`, `_getBubbleText`, `_getBubbleCopyText`, `_bubbleAnchorId`, `_resetBubbleDeleteBtn`, `_resetAllBubbleDeleteBtns`, `_handleBubbleDeleteClick`, `_deleteTurn`, `_makeBubbleDeleteBtn`, `_setDeleteIcon`, `_setActionIcon`, `_renderActionIcons`, `_setBubbleModel`, `_setBubbleModelFromMeta`, `_modelLabelFromMeta` | Per-bubble action row (footer): **per-turn model tag** (`model EFFORT`, e.g. `deepseek-v4-flash HIGH`, left-truncated so the model's end stays visible), collapse/expand, read-aloud (SpeechSynthesis), copy, and per-turn delete (two-click trash → ⚠️ → confirm, resolved server-side by walking the parent chain). The footer renders on **streaming** bubbles too — a live reply, or one being recovered from the DB by the reconcile loop, gets the row as soon as it has real text (placeholder `…` is skipped); only the destructive **delete** button is held back until the turn finalizes (the streaming class drops → `_setBubbleText` re-calls `_addBubbleActions`, which adds delete via the reuse branch). The model + reasoning-effort come from the assistant interaction's `metadata` (persisted by the loop's `_build_meta`) on history/reconcile, and from `app._activeTurnModel`/`app._activeTurnEffort` (set in `chat-activity.js` from the live `llm_call_start` event before the first token) on a fresh turn. Sets `app._addBubbleActions` at module scope. |
| `chat-stream.js` | `_stripToolCalls`, `appendStreamToActiveBubble`, `finalizeAgentResponse`, `ensureStreamingBubbleForActiveTurn`, `finalizeAgentStep`, `markAgentInterrupted`, `seedStreamingBubble`, `attachToolCallsToLastBubble`, `_setBubbleText`, `_findAgentBubbleForTurn`, `_wsTurnBuffers` | Live streaming from WebSocket: accumulates chunks per turn (`_wsTurnBuffers`), finalizes/interrupts agent steps, attaches tool-call accordion panels to agent bubbles. **Lazy tool-call bodies:** opening the group is cache-only; expanding one row fetches only that call from `/session-tool-detail` and keeps it in memory for the visit. Live calls already carry their bodies. Sets all streaming `app.*` methods at module scope. |
| `chat-send.js` | `sendMessage`, `sendStopMessage`, `abortChatStream`, `applyChatGate`, `_canChat`, `_autoResizePill`, `_updateScrollIndicator`, `_updateInputRowState`, `_saveDraft`, `_clearDraft`, `_restoreDraft`, `_renderPendingBubbles`, `_startOutboxPoll`, `_outboxHasPending`, `_persistLastSessionSeq`, `_loadLastSessionSeq` | Message sending pipeline: outbox retry queue (survives refresh), draft persistence, chat gate (sign-in check), session_seq persistence, self-healing watchdog, stop/interrupt, `/btw` snapshot-fork widget dispatch, pill textarea auto-resize + scroll indicator dot. Sets `app.abortChatStream` and `app.refreshChat` at module scope. `app.refreshChat` (the 60s self-healing backstop) is guarded by the same remote-change check as `refreshTranscript`: unchanged → no DB resync/re-render (still clears a stuck "processing" state so the composer recovers); changed → full clean reload. |
| `chat-ui.js` | `initChat` | Wires everything together: sets remaining `app.*` methods (`app.updateLastBubble`, `app.autoResizeChatInput`, `app.sendChatMessage` — the exported `sendMessage`, so shared modules like the footer compaction panel's "Compact now" can stage `/compact` + send, etc.), binds chat input/keyboard/send events, execution mode toggle, continue/stop buttons with 500ms poll, scroll-to-bottom chevron with auto-scroll lock, input area padding (ResizeObserver), mobile focus-on-first-tap, initial gate + draft restore. |
| `chat-terminal-engine.js` | `initTerminalChatEngine`, `activateTerminalChat`, `deactivateTerminalChat`, `sendTerminalInput`, `focusTerminalChat` | **Terminal Chat** agents (engine `terminal_chat`): replaces the whole bubble area with a live xterm.js terminal bound to a PTY (shared registry in `app/api/terminal.py`). On session load `activateTerminalChat` POSTs `/api/v1/chat/terminal-chat/activate` to get/create the PTY id, mounts xterm, and opens the terminal WS for output (string frames are JSON control — ping is answered with pong, never painted). `term.onData`/`onResize` forward keystrokes **and mouse events** (when the program enables mouse reporting) + viewport size to the PTY over the WS — the same mechanism as the admin terminal (`ui/shared/js/terminal.js`); Shift+Tab is intercepted to CSI Z. The chat pill sends single lines over HTTP `/write` (carriage-return Enter) via `chat-send.js`. On mount it **lazily imports the plugin-owned on-screen keys** (`/plugins/engines/terminal_chat/ui/terminal-keys.js`) and hands them `sendTerminalInput`/`focusTerminalChat`; on unmount it calls their `unmountTerminalKeys()`. Sets `app.terminalChatKey`/`app.terminalChatFocus`. |
| `chat-components.js` | `initChatComponents` | Renders server-validated declarative agent components into the single agent panel (`#chat-component-panel`, CHAT-COMPONENT-PANEL). The panel's ONLY open state is the FULL VIEW (CHAT-COMPONENT-FULL-VIEW, CHAT-COMPONENT-SILENT-RESTORE): a full-height overlay pinned below the chat header tabs and **above** the composer — the composer stays visible and usable — sized flush with the transcript's content width (`chat_common.content_max_width`); there is no drawer and no ⛶ expand control, and the panel starts closed on every load. The header's grouped "Elements (n)" tab (one tab for every plan / checklist / component, mirroring "Spawns (n)") opens it, a row in that dropdown selects an element (newest first), and the (—) header button closes it. The initial interactive component is a persistent `todo_list`. |
| `chat-task-frames.js` | `initTaskFrames` | Legacy task-border renderer retained for compatibility but no longer initialized by chat. Task grouping remains a backend context-management concern and has no visible chat chrome. |

| `chat-changes.js` | `initChatChanges`, `refreshSessionChanges` | Admin-only working-tree **data feed** for the chat footer: polls the session's dirty path list, broadcasts every result as `chat-changes:updated`, and exposes `app.refreshSessionChanges`. Renders nothing — the 'changes' chip (count badge + toggle) and the 'local_changes' panel (file list + commit) consume the events. Replaces the old session-changes drawer, which is gone from the app. |
| `chat-zoom.js` | `initChatZoom`, `setChatZoom`, `resetChatZoom` | **Pinch-to-zoom for the chat transcript only** (two-finger pinch on touch, Ctrl+wheel on trackpad/desktop) — scales `#chat-messages-inner` via CSS `zoom` so fonts AND layout zoom together while the rest of the app stays put. Persists the level in localStorage (`chatZoomLevel`), restores on boot, and shows a floating −/%/+/reset chip while active. Stays consistent with the virtual scroller via `scaleVirtualScrollHeights` (chat-virtual-scroll.js) — heights are cached in zoomed px, so the zoom module rescales them by ratio and placeholders divide their inline height by the container zoom (`_containerZoom`). |
| `footer-gesture-forward.js` | `forwardFooterGestures` | Routes **wheel and touch gestures that begin over the chat footer** (composer pill + control rows) to the transcript scroller. The footer has no scrollable ancestor — `#chat-panel`, `#stage` and `<body>` are all `overflow:hidden` — so a gesture that starts there has nowhere to go and never reaches `#chat-messages`. Touch has no wheel-style chaining, so the drag is translated 1:1 into `scrollBy()`; wheel is chained. Each forwarded gesture also records **transcript scroll intent**, so the turn-anchor / soft-snap logic treats a footer swipe exactly like one over the messages (the reader is scrolling; the current turn must not reclaim the viewport). Nested scrollables inside the footer keep their own gesture. Kept in sync with the pill's `applyRubberBand({ wheel: false })` in `chat-ui.js` — that guard stops the non-scrollable pill from `preventDefault()`ing the same gesture at a boundary it can never satisfy. |

## Data layer (shared between chat and session modules)

| Module | Exports | Purpose |
|--------|---------|---------|
| `chat-message-cache.js` | `_messageCache`, `_CACHE_TTL_MS`, `_sessionFocus`, `_FOCUS_MAX`, `_WINDOW_RADIUS`, `_loadingSessions`, `_loadSessionFocus`, `_persistSessionFocus`, `_captureSessionFocus`, `_cacheAppendMessage`, `_rememberSessionManifest`, `_transcriptChangedRemotely` | In-memory message cache (Map keyed by sessionId, 60s TTL), per-session scroll-position persistence (app_cache rows via `kvCache`, `chat:focus:<sessionId>`, up to 50 sessions), windowed-render constants. `_cacheAppendMessage` is used by both the WS streaming path and the session loader to keep the cache in sync. **Transcript manifests (remote-change detection):** keeps each session's last-known server manifest (`authority_revision` + `content_hash`, persisted to app_cache `chat:manifest:<sessionId>` via `kvCache`) and `_transcriptChangedRemotely` asks the server via `/session-messages?manifest_only=1&known_revision=&known_hash=` whether the transcript changed. Every refresh path consults this FIRST and must do NOTHING to the screen when the server says `not_modified: true`. Legacy localStorage blobs (`sessionFocus.v1`, `sessionManifest.v1`) are registered as migration seams via `kvCache.registerLegacyMap` and removed once copied into IndexedDB. |
| `chat-virtual-scroll.js` | `_bubbleHeights`, `_placeholderIds`, `_virtualScrollHandler`, `_VS_BUFFER`, `_storeBubbleHeight`, `_getBubbleHeight`, `_makePlaceholder`, `_recycleVisible`, `_recyclePlaceholderToBubble`, `_hookAddChatBubble`, `_installVirtualScroll`, `_teardownVirtualScroll`, `_loadingMoreMessages` | Bidirectional virtual scrolling: replaces finalized off-window bubbles with height-preserving placeholders and materialises only the buffered viewport. Streaming/focused/expanded bubbles stay live. Hooks `app.addChatBubble` to auto-store heights. Used by session-load for efficient session switching. |

## Session modules (dropdown, lifecycle, loading, agent selection)

| Module | Exports | Purpose |
|--------|---------|---------|
| `session-list.js` | `_sessionsCache`, `populateSessionSelect`, `_renderSessionRows`, `_setTriggerLabel`, `_clearSessionHeader`, `_fetchRelatedSessions`, `applySessionTitle`, `_formatRelativeTime`, `_truncate` | **Compatibility re-export shim** — the session-list logic now lives centralized in `ui/chat/elements/session-dropdown/list.js` (see the elements table below); this file re-exports it so existing importers keep working unchanged. Session dropdown list: fetches sessions from `/api/v1/db/sessions`, renders rows with drag handles, pin icons, status spinners (running/unread), spawn badges, relative timestamps. **Reliability policy:** the fetch validates `res.ok` + a real `sessions` array, NEVER clobbers a warm cache with an empty/invalid result (the server can answer 200 with `{"sessions": []}` when a mid-query exception is swallowed), and retries with bounded backoff — a cold cache keeps the skeleton phantom rows visible while retrying, so the dropdown always converges to the real list. Manages the header label and related-sessions chips — a persistent spawn-family tab bar (a "Main" tab for the orchestrator plus one tab per spawned helper — and per **delegated saved agent** (a `delegate_task_to_agent` target, carried as a `role: 'delegate'` child with a `share-2` icon and the agent's name as its label) — identical whether viewing the orchestrator or any member, with the currently-open session highlighted), plus browser-session tabs. The family + active highlight come from `/related`'s `orchestrator`/`spawns` fields. `applySessionTitle` handles the live titler from the WebSocket. `_clearSessionHeader` blanks the header synchronously when a switch begins (label/icon/status/agent-name/mode/target/chips + the dropdown's `data-loaded` "not loaded" CSS state) so the old session's identity never lingers while the new one loads. |
| `session-core.js` | `interruptSession`, `switchToSession`, `deleteSession`, `patchSession`, `togglePin`, `startRename`, `_headerRenameSession`, `autoRenameSession` | Session lifecycle actions: switching sessions (teardown, loading spinner, load chat, drain replayed events, send WS resume), deleting (interrupt run + DELETE API + switch to next or create fresh), pinning (PATCH), inline rename (dropdown row + header long-press, both use the same inline-input pattern), and **auto rename** (`autoRenameSession` — POSTs to `/api/v1/db/sessions/{id}/auto-title` so the Session Namer app function re-titles the session on demand, forced past any lock or special prefix; falls back to a first-message title in browser-storage mode). |
| `session-agent.js` | `_agentsCache`, `_lastSessionPerAgent`, `_loadLastSessionMap`, `_saveLastSessionMap`, `findWebagentAgent`, `createWebagentAgent`, `ensureWebagentAgent`, `populateAgentSelect`, `_refreshAgentAbilities`, `_agentIconFor`, `_setAgentTriggerLabel`, `_renderAgentRows`, `_fetchAgentRunningStatuses` | Agent selection: loads agents from API, manages the agent cache (`_agentsCache`), the last-session-per-agent map (localStorage), and the WebAgent singleton (find-or-create from the `default` template). `populateAgentSelect` sets `app.currentAgentId`. Abilities cache (`window.__currentAgentAbilities`) gates the "Send to agent" button. |
| `session-load.js` | `loadSessionChat`, `refreshTranscript`, `_maybeLoadMoreOnScrollTop`, `_showDebugBubble` | Core session loader: paints a valid IndexedDB transcript immediately, shows a UI-only mock progress note (“Assessing…”, rendered through the same live-activity mirror the run notes use) while it validates the server manifest in parallel, and applies an authoritative replacement only when changed. The note becomes `Server connection is currently unavailable.` during retryable connection failure. Tool bodies never enter the light transcript; opening a group is local and one row fetches one body from `/session-tool-detail`. Windowed paging, focus restoration, reconcile cursors, and explicit refresh remain supported. |
| `session-swipe.js` | `_initPinSwipeNavigation` | Touch/pointer swipe between pinned sessions: horizontal drag slides the current transcript away and reveals the next pinned session's bubbles (preloaded from cache). Includes desktop prev/next buttons. **Background neighbour warming:** pre-loads ONLY the next + previous pinned sessions (the two the arrows/swipe can reach next) so navigation feels instant, and ONLY when idle — every warm fetch is `requestIdleCallback`-scheduled (timer fallback), runs one-at-a-time at `priority: 'low'`, is `light=1`, mirrors what a real open would download (anchored `around_id` window when that neighbour has a saved scroll position, else newest), and is skipped while a turn is running / the active session is loading / the tab is hidden. Exposes `app.warmNeighborSessions` (the active-session loader calls it once a load settles) and `app.abortNeighborWarm` (the loader calls it the instant a new load begins, so a warm can never compete with the on-screen session). |
| `session-notification.js` | `initSessionNotification`, `checkSessionCompletions` | **One state model, two surfaces.** A notification IS an unread, settled session: the row set is derived from `_sessionsCache` with the SAME predicate the Agents → Sessions page chip uses (`sessionAckFlag` — `has_unread` AND a settled flag), so the panel and that page list the same sessions by construction. (The panel used to be an EVENT log — only the `running → done` transitions observed while the tab was open, i.e. a small, recent, mostly-green subset of that state view.) Lifetime is the DB's own read state, never client bookkeeping: the row's ✕, "Clear all", the session's own flag chip, or marking it read elsewhere writes `sessions.read_at` and the row goes — opening a session deliberately does NOT acknowledge it, so glancing through sessions leaves their rows in place; marking the session unread writes `sessions.unread_at` and the same row returns — one acknowledgement shared with the chip, replicated across devices. **Desktop** renders them as inline clickable pills in the header's right cluster (`#session-notification-inline`, authored in `index.html` immediately left of the Recorder control): each pill leads with the flag's own glyph + label (`resolveSessionFlag` — the closer's verdict, with `run_status` as the fallback), then the ellipsized session name, the closer's note and a live relative timer, and opens that session on click; the header counter beside the Chat label is the same control on every layout — it shows the unread count and toggles the draggable panel `#session-notification-container`, so desktop runs the pills AND the panel together (dual notifications) while mobile keeps the panel alone. The panel's rows read session name / closer note / timer on three lines. Re-renders on the 800px breakpoint crossing, re-stamps every row's flag on each reconcile (a closer record lands a beat after the status flips). Reconciled from `_sessionsCache` on the 15s poll and on every session-list republish (`sessionDropdownStore.subscribe`). The per-user `session_notifications` table and `/api/v1/db/session-notifications` are no longer read by the UI (kept for existing deployments and the hybrid-sync payloads). Hooked into the poll in `session-init.js`. |
| `session-init.js` | `registerSessionApi`, `initSessions` | Entry point: `registerSessionApi` sets `app.populateSessionSelect`, `app.populateAgentSelect`, `app.loadSessionChat`, `app.applySessionTitle`, `app.reloadCurrentSession` and wires focus persistence. `initSessions` orchestrates the chat header: **mounts the session-dropdown controller** (logic centralized in `ui/chat/elements/session-dropdown/` — controller.js + list.js; mounted here for the static chat-side-panel.html markup, since the control loader reuses existing DOM without calling the element's `init()`), wires the agent-name dropdown + agent picker popup (+ button), header delete button, **header refresh button** (resets the transcript via `refreshTranscript`), TUI bridge status poll, session list poll, **completion notification init**, and swipe navigation. Boot sequence: `populateUserSelect` → `populateSessionSelect` → `loadSessionChat`. |

## Boot order

1. **Module evaluation** (ES import time) — all `app.*` assignments at module scope run immediately in dependency order
2. **`initChat()`** — sets remaining chat methods, wires input/send/stop/continue, execution mode, scroll chevron, gate, draft restore
3. **`registerSessionApi()`** — sets session API methods on `app`, loads saved focus positions
4. **`initSessions()`** — builds dropdown UI, agent picker, header buttons, starts polling (TUI bridge, sessions, related sessions), runs boot sequence (user-panel → sessions → load current chat)
