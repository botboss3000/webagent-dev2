# Codebase Admin — v3

For Rust v3 development and v2 feature ports, read `plugins/abilities/Administrator/codebase_admin/skills/v3_migration.skill.md` within the seeded `webagent-v3/` snapshot using `file_read`. It explains the actual-UI migration workflow, Rust backend contracts, deployment boundaries, and investigation lessons. The current v3 catalog loads this main guide and tool guides, not individual `skills/` files automatically.

Use this ability for source work inside the current session workspace. The workspace is separate from the WebAgent host checkout and other application data. Inspect the workspace first. For WebAgent v3 source work, use `workspace_seed` to create a clean source snapshot and Git baseline in `webagent-v3/`. It never imports live data or credentials. For other repositories, report a missing source prerequisite rather than editing a similarly named file elsewhere.

Use `prompt_slot_read` to list or get the shared_default agent's ordered instruction slots. Each slot has a revision. `prompt_slot_write` can put or delete a slot only after approval; supply the revision you just read (0 to create). A stale revision is rejected. Changes affect newly accepted runs; an in-flight run retains its pinned instructions. The v3 app supports one administrator and agent, with no per-user overrides yet. `__skills__` is reserved and cannot be managed as an ordinary prompt slot. Never store credentials in a prompt slot.

Use `state_inspect` for bounded, read-only facts about the current session. Start with `catalog` to discover available resources. `session` gives title and chat cursor/count; `chat` pages public message previews using an ascending sequence cursor; `runs` gives recent status metadata. The runtime binds the session; there is no session ID, SQL, database path, or encryption key argument. Do not use shell or Python to access application databases.

Read project instructions in the workspace before changing source. Search for the owning file or symbol, then read a focused region. Make the smallest coherent change, use `source_review` to inspect tracked and new files, and verify it with the available workspace commands. For a multi-file edit, `source_patch` applies a checked text diff against the exact review digest and requires approval. The image includes Rust 1.90; use `cargo check` or `cargo test --locked` from `webagent-v3/` for Rust changes, with a bounded command timeout. After verification, call `promotion_propose` with the exact digest from a complete `source_review` and a concise summary. This creates a durable review request; only the signed-in administrator can approve promotion to live v3 source or reject the proposal. Record what changed and what remains unverified.

The session capability mode also applies: `read_only` withholds mutating tools and denies a queued mutation even if its approval was granted before the mode change. A mode change invalidates pending approvals. `write` still obeys the global policy; it does not turn approval-gated tools into automatic actions.

The Rust policy gate decides whether each tool is allowed or requires approval. A loaded ability does not override that gate. File writes, exact edits, patches, shell commands, and Python execution require approval by default. A command's effect matters more than its name.

This port covers typed current-session inspection, revision-checked prompt slots, source seeding, workspace listing, reading, searching, writing, exact editing, checked patching, change review, shell, and Python. v2 checkout/checkin, automatic repository promotion, and server restart are not available in this ability yet.
