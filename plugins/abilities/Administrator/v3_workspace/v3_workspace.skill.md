# V3 Workspace
Use this private adapter only for trusted administrator development. It is separate from v3 account authentication and does not import v2 credentials or grant v3 tool approvals. Call status first. Seed a canonical UUID workspace, read source, obtain a complete review, patch against its exact digest, and run fixed locked Cargo checks/tests against a matching review. Obtain a fresh complete review before proposing.
Every action has a stable request ID. Same ID/body returns its original receipt, not current state. Use a NEW ID for fresh reads/reviews. Changed retries are rejected. After timeout/restart, inspect the receipt and current review; never silently replay uncertain mutations. A proposal is a frozen adapter artifact, not an applied v3 promotion. Do not claim it appears in v3's promotion UI. For live integration, register an open task with the V3 Build bridge, then pass the reviewed text diff to its checked `v3_source_apply` tool with that registered task's `workspace_inputs_sha256` from `v3_build_work_status`. The checked apply changes only the task's isolated snapshot. Inspect its durable source receipt after uncertainty. A workspace proposal alone has no release effect. `v3_build_finish` freezes this task and immediately queues its own serial development build and deployment, subject to approval.
The adapter runs on its configured private host. It executes trusted repository build code and is NOT a hostile-code sandbox. Keep state outside the checkout, protect token files, use an isolated unprivileged account/host, and enforce private-network ACLs. Do not supply arbitrary commands, URLs, environment, credentials, database paths or live targets. Do not auto-enable this ability on the running agent.

## Existing login bridge fallback
When V3_WORKSPACE_WORKER_URL is absent, tools reuse login_as_current_user_v3 with the run-bound caller/session. This verifies the independent v3 administrator and allows only existing GET APIs: source review and promotion receipt. Here workspace_id means an existing v3 session UUID, not an adapter workspace. Receipt lookup requires workspace_id; it reads a promotion receipt, not a worker operation receipt.
This mode cannot seed, patch, read files, run Cargo, or propose. Those operations explicitly return unsupported. Use v3's approval-controlled agent tools or the dedicated worker. V2 login is not v3 authentication. The controlled browser is closed after each read. No configured-worker failure silently falls back.
